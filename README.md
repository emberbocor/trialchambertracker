# Trial Chamber Tracker

Know which trial spawners are ready and which vaults you still have to open.

Trial Chamber Tracker puts a small label above trial spawners and vaults. A trial spawner that is cooling down shows how long until it can be challenged again. A vault shows whether you have already opened it, and your opened vaults are remembered, so the labels still tell you the truth from across the chamber and after you log out and back in.

Available for NeoForge, Forge and Fabric. Client-side only: it works on any server, also on vanilla and Paper servers that do not have the mod.

## Features

- **Cooldown timer.** A trial spawner in cooldown shows `Cooldown 29:41` in white, counting down to the moment it can be activated again. Ominous trial spawners show `Ominous cooldown 12:05`.
- **Vault markers.** A vault you can still open shows `Ready` in green (`Ominous: ready` in aqua for ominous vaults). A vault you have already opened shows `Opened` (`Ominous: opened`) in red.
- **Seen from anywhere nearby.** Labels behave like player name tags: bright when nothing is in the way, faint but still readable through blocks and mobs. A vault on a ledge above you tells you whether it is worth climbing up. Labels are shown within the display range (32 blocks by default) and disappear with the rest of the HUD when you press F1. Seeing them through blocks can be turned off.
- **Learns the server's cooldown.** If a server uses a different cooldown length, the mod measures it the first time you watch a cooldown end and uses it from then on.
- **Remembered.** Cooldowns you have seen start and vaults you have opened are saved per world or server, so the labels survive leaving and rejoining, also when you are far away from the vault.
- **Self-correcting.** Whenever the server shows something newer, the saved data follows it: a spawner that is no longer cooling down loses its timer, a vault that the server lets you open again goes back to `Ready`.

## How it works, and its limits

Servers only send part of the trial spawner and vault data to the client. The mod uses only what a vanilla server sends, so everything below holds on any server.

### Cooldown timer

- A vanilla server does not send the end of a cooldown or its length to clients. The timer therefore starts when your client sees the spawner finish: when the last mob of a wave dies (or, if you arrive a little later, when the shutter opens to eject the reward).
- The server does not send the cooldown length either. The mod starts with the vanilla length of 30 minutes (36,000 game ticks), which all trial chambers generated by vanilla use, for normal and ominous spawners alike.
- Servers, maps and data packs can change that length. The mod learns it: when you are within 32 blocks of a spawner while its cooldown ends, and you also saw that cooldown start, the measured length is saved for that world or server and used for every timer there, also for timers that are already running. Until then, a changed length shows a wrong time (the label stays correct about the spawner being in cooldown). If spawners in one world use different lengths, the last measured one is used.
- When the cooldown had already started before you saw the spawner finish (for example, someone else cleared it while you were away), the label shows `Cooldown` without a number.
- The cooldown runs on game time, like on the server. It keeps running while you are offline or far away, and the timer is right again when you come back.
- At `0:00` the cooldown is over. The spawner switches back as soon as the server ticks it again, which only happens while a player is within the server's simulation distance.
- An ominous spawner that is triggered again by a player with Trial Omen during its cooldown loses its timer, because it is no longer in cooldown.

### Vault markers

- A vanilla server tells clients which players near a vault (about 4 blocks) can still open it. The mod reads that list for you only: when you stand within 3.5 blocks of a vault for a moment and you are not on the list, you have opened it; when you are on the list, you have not.
- So a vault is marked as opened right after you open it, and also when you walk up to a vault that you opened before installing the mod.
- From farther away the server sends nothing about vaults, so the label shows what was saved. A vault you have never been close to shows `Ready`.
- Spectators are never on the list, so nothing is changed while you are in spectator mode.
- Opened vaults are saved per player, so several accounts can share one game folder.

## Requirements

| | NeoForge | Forge | Fabric |
|---|---|---|---|
| Minecraft | 26.2 | 26.2 | 26.2 |
| Java | 25 | 25 | 25 |
| Loader | NeoForge 26.2.0.0-beta or newer | Forge 65.0.0 or newer | Fabric Loader 0.18.4 or newer |
| Other | | | Fabric API 0.152.1 or newer |
| Jar | `trialchambertracker-neoforge-26.2-<version>.jar` | `trialchambertracker-forge-26.2-<version>.jar` | `trialchambertracker-fabric-26.2-<version>.jar` |

On Minecraft 26.2, NeoForge and Forge are separate loaders that do not run each other's mods, so each has its own jar. Pick the jar that matches your loader.

Use the loader build for Minecraft 26.2. Forge uses series 65.

### Client and server

The mod only reads what the server already sends and draws labels, so it is purely client-side on every loader.

- Install it on the client only. It does not need to be on the server, and a client with the mod can join any server, modded or vanilla, whatever loader the server uses. It adds no blocks, items, network messages or registries.
- Installing it on a dedicated server does no harm: Forge and Fabric skip it there, and on NeoForge it does nothing.

## Configuration

### Client: `config/trialchambertracker-client.json`

```json
{
  "showSpawnerTimers": true,
  "showVaultMarkers": true,
  "showThroughBlocks": true,
  "displayRange": 32
}
```

- `showSpawnerTimers`: show the cooldown timer above trial spawners. Default `true`.
- `showVaultMarkers`: show the ready / opened marker above vaults. Default `true`.
- `showThroughBlocks`: show labels faintly through blocks and mobs, like player name tags. With `false`, a label is hidden by anything in front of it. Default `true`.
- `displayRange`: how far away labels are shown, in blocks, measured straight from your eyes to the block (up and down count too), a whole number from 1 to 64. Default `32`. Trial chambers usually lie 80 blocks or more below the surface, so with these values their labels normally do not show up on the surface above them.

The file is created the first time the mod sees a trial spawner or vault, and read again every time you join a world or server or change dimension. An invalid or missing value is replaced by its default, with a warning in the log; the file itself is not changed.

Turning a label off only hides it. Cooldowns and opened vaults are still tracked and saved.

## Saved data

The tracked data is stored in the game folder (next to `config/`), never inside a world save:

```
trialchambertracker/singleplayer-<world folder>-<hash>.json
trialchambertracker/server-<server address>-<hash>.json
```

Singleplayer worlds are identified by their folder name in `saves/`, servers by the address you connected to (the same server under two addresses gets two files). Inside are the learned cooldown length (once measured) and, split by dimension, the game time at which each known cooldown started and the vaults each player has opened. Deleting a file only makes the mod forget; nothing in the world changes. The data of the world you are in is kept in memory while you play, so close the game before you delete or edit a file. Renaming a world in the game menu keeps its folder, so the data is kept.

## Compatibility

- Works with any mod that keeps the vanilla trial spawner and vault blocks. Trial spawners and vaults added by other mods as different blocks get no labels.
- Mods or server plugins that reset vaults or change cooldowns are handled by the self-correction described above; a changed cooldown length is learned as described under "Cooldown timer".

### Upgrading a world from 26.1

Use Java 25 and the 26.2 jar for your loader. Keep `config/trialchambertracker-client.json` and the `trialchambertracker/` folder in the same game folder: their format is unchanged. A world kept under the same save folder name, or a server reached through the same address, keeps its learned cooldown length, known cooldown starts and opened vaults.

## Building from source

```
./gradlew build
```

The jars are written to `neoforge/build/libs`, `forge/build/libs` and `fabric/build/libs`. The project follows the [MultiLoader-Template](https://github.com/jaredlll08/MultiLoader-Template) layout: shared code lives in `common`, loader-specific code in `neoforge`, `forge` and `fabric`.
